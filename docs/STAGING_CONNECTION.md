## Authenticated staging UAT

With the same ignored local environment loaded, run
`node scripts\test_authenticated_cloud_staging.mjs`. It signs in the existing
Developer, creates synthetic Admin and Outlet test identities only through the
authenticated Developer API, and keeps generated temporary passwords in memory
only. It verifies user-management audit records, session lifecycle, role/store
isolation, direct-write denial, private image lifecycle, and synthetic closing

project other than the approved staging ref.

The authenticated UAT also verifies private-image replacement cleanup,
zero-variance finalization rejection, and authenticated daily/monthly CSV
downloads. Export data is generated by the Edge Function from finalized rows
in the active authorized store; the browser only receives the completed
download payload and never receives a service-role key.

operator must verify the unchanged Review/Print DOM, actual clipboard paste
after a user gesture, signed private image reload, and Developer/Admin/Outlet

The current organization is on the Free plan. Supabase's leaked-password
protection is therefore **PLAN-GATED** and must not be enabled by upgrading or
changing billing without explicit approval. It is a required production
security decision. Staging enforces a 12-character minimum plus uppercase,
lowercase, numeric, and symbol classes for Developer-made temporary passwords;
generated synthetic test passwords are held only in process memory.

The advisor's two `SECURITY DEFINER` notices are accepted/explained only for

path, validate authenticated identity, enforce role/store scope, and have

index notices are expected on the young synthetic staging dataset and must be
preserved until realistic workload evidence exists.
